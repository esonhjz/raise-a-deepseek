私有宿主当前已推进到 **M2 情绪连续性与 M3 每周回顾首版**：M1 的存储、自然经历捕获和统一恢复工具已实现，M2/M3 的代码与隔离回归已部署。M1 的自然事件体验、M2 的真实表达、M3 的自然生成及长期质量仍分别待验收，三个里程碑均不标整体完成。

## 当前限制

- 生产召回仍是字面匹配。FTS5 候选实现不能解决所有同义表达、指代和历史事实问题。
- 原有 JSON MemoryStore 是简单单写者示例；需要并发写入时使用新 SQLite API。
- SQLite 纠正、主题遗忘和文本过滤仍含关键词启发式，可能误删或漏删；它们不等于完整语义理解。
- 时间线已能保守记录部分普通陈述；复杂指代、反讽、同义对象和长叙述可能漏记，不能宣称自然语义提取已完成。
- 单条遗忘先预检长期记忆与时间线；有多候选时询问，不猜。主题遗忘仍为词面批量，可能误删或漏删。
- 私有宿主已有统一两库恢复包；旧的单库格式作为受锁兼容入口保留。包不含 QQ 登录、DSH 会话、权限或发送队列。
- 维护协议覆盖已接入的桥接、存储和维护工具，不阻止绕过模块直接写 SQLite 的外部脚本。旧快照恢复可能撤销之后的纠正或遗忘。
- 完整来源别名、工具观察证据、多轮指代和生产恢复仍有未验证范围，见[恢复设计](RECOVERY.md)。
- 日记是主观解释；来源 ID 存在不证明每个推断都正确。
- 周回顾生成和召回都检查来源状态；同篇日记有来源失效时，未经来源拆分的心情、感受和想法不进入生成。规则仅覆盖现有来源映射，不等于任意正文都获得语义证明，详见[周回顾设计](WEEKLY-REVIEW.md)。
- 已知日记跨日会话缺陷已经修复，但历史失败记录和旧会话保留，不自动补写。没有真实新生成就不把修复写成生产内容质量通过。
- 原文或数据可因软删除保留在磁盘、QQ、服务端及备份中；召回排除不等于安全擦除。
- 本仓库不提供 QQ 连接器、DSH 会话执行器、电脑控制、情绪连续性、自动日记、周回顾、图片发送、完整时间线或统一恢复工具。公开 SQLite 核心也不包含私有宿主的运行登记与跨库维护锁。

## 下一步

1. 在真实 QQ 使用中逐步验收自然经历保存、查询、计划/进展、遗忘及持久化，不清空主号上下文，不为测试虚构事件。
2. 在普通对话中观察情绪背景是否轻微延续、换话题是否自然、遗忘后是否停用依据，不为测试制造冲突。
3. 等待日记与周回顾自然触发，再做来源、人物时间和自洽性抽查；不强制生成、不为了数量伪造或集中补写。
4. 按独立提取、合成测试和可复现示例继续开放通用模块。
5. 统一恢复工具保持离线维护边界，生产恢复仍未验证；不为验收主动替换生产库。
