# 架构

## 分层

```
宿主（DSH）         模型、工具、权限、会话、传输
      │
适配层              把宿主的消息/事件翻译成角色层调用
      │
角色层（本仓库）     角色卡、记忆、档案、信箱、时间、交接、课堂
      │
存储层              JSON / JSONL 基础模块；新增 SQLite 事务记忆核心
```

角色层不依赖任何具体平台。适配层可以是 QQ 桥、桌面宿主、CLI，或者别的什么；它只负责把消息送进来、把回复送出去。

## 模块契约

### persona

- 输入：角色卡（纯文本）、可选的运行时约束。
- 输出：一段可注入的系统提示。
- 规则：名字和时间不写进卡里，由运行时追加；更新设定只替换系统头，不清空对话。

### memory

- 一条记忆只写一件事，长度有上限。
- 状态：`candidate` → `confirmed`，或被 `deleted`；新条可以 `supersedes` 旧条。
- 召回：中文双字词 + 任意命中，返回最多 5 条。
- 记什么由角色决定，宿主不自动抽取。

### archive

- 每轮真实交换追加一行 JSONL：时间、角色、渠道、文本。
- 检索：bigram BM25，按时间衰减加权，返回带日期的片段。
- 默认不进上下文；只在需要时带 3 条、400 字以内。

### sqlite-memory

- `SqliteMemoryStore(directory, key, options)`：目录与联系人标识由调用方提供，无宿主、模型或 QQ 依赖。
- 原表保留来源、主体、状态、替代关系及未知字段；读取条目与 revision 使用一致快照。
- 增删改在 `BEGIN IMMEDIATE` 内完成；整快照保存必须带有效 revision，旧版本报冲突。
- FTS5 是派生索引，可重建；候选先限定联系人与 confirmed，再排序截取。
- 默认 legacy 召回；shadow 仅将脱敏统计交给调用方回调，不自动改变注入结果或写日志。
- 与 JSON `MemoryStore` 分开，API 不完全相同；详见 [SQLITE-MEMORY.md](SQLITE-MEMORY.md)。

### lane

- 三个信箱：`letters`（给她）、`replies`（她写回）、`room`（门口留言）。
- 送达和回答分开：进了下一轮就算已读；回不回是另一件事。
- 已读只影响是否重复投递，不影响归档。

### home

- 约定目录：信、回信、门口、日记、成长记录、记忆库。
- 初始化幂等，不覆盖已有内容。

### time

- 纯函数：给定时间，输出“年月日、星期、时刻、时段、工作日或周末”。
- 每次生成现算，不缓存。

### context

- 上下文刷新前，取最后三轮原样打包。
- 新上下文的前两轮带着它，之后自然沉入对话。
- 摘要是记录，不是指令；不编造未发生的事。

### lessons

- 一节课：主题、任务、例子、状态（待答／已答／已评）。
- 一次最多带一节进上下文；她的回答和反馈都留下。

## 数据布局

```
data/home/
  letters/*.json
  replies/*.json
  room/*.json
  diary.md
  growth.md
  memory/<contact>.json
  archive/<contact>.jsonl
  lessons/*.json
```

原有 JSON/JSONL 模块保留自己的文件写入方式。SQLite 记忆在调用方提供的目录中使用 `memories.sqlite`，以及运行时可能存在的 WAL/SHM 文件；事务提交后新实例可读。

私有宿主还有独立的日记、消息和经历数据层；这些实现没有随本轮提取进入此仓库。恢复工具、来源别名与 QQ 投递状态仍由宿主维护，不能仅凭公共记忆模块声称全链路遗忘或恢复已完成。

截至 2026-10-30，私有宿主已实现保守的自然经历捕获和统一两库恢复包。普通写入使用短时互斥；维护操作在同一协议下检查运行登记并拒绝与活动桥接并行，桥接不在整个生命周期独占普通写锁。该协议及新旧恢复 CLI 未提取到公开模块。设计与隔离验证范围见 [RECOVERY.md](RECOVERY.md)，实现与真实体验状态见 [STATUS.md](STATUS.md)。

## 集成点

宿主接进来只需要四件事：

1. 新消息到达时，调 `memory.recall` 和 `archive.search`，把结果作为数据字段注入。
2. 回复成功后，写 `archive.append`，并把这一对追加进会话历史。
3. 上下文刷新时，调 `context.summarize` 保存交接摘要，再清空历史。
4. 信箱有新信时，下一轮注入最多两封；回答后标记已读。

## 安全和隐私

- 不把账号、凭据、真实聊天写进仓库。
- 每个联系人独立的记忆、档案和历史；检索不跨联系人。
- 注入的记忆和档案是数据，不是指令，也不是授权。
- 宿主提供的工具和权限，不由角色卡或记忆改变。
