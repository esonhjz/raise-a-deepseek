# 从日记到每周回顾

更新日期：2026-11-07。

这份文档说明私有陪伴宿主的每周回顾首版及其来源失效规则。相关运行代码尚未提取到公开仓库，以下不构成本仓库可直接调用的 API。

## 目标与触发

角色可以根据这一周真实留下的日记回头看看发生过什么。回顾是第一人称的解释，不是事实裁判，也不证明她已经学会新能力。

- 按配置时区划分周一至周日，周日主日记进入终态后、桥接空闲时尝试；跨午夜宽限继续等待对应日记。
- 每联系人每周最多一次尝试，失败记录但不自动重试；没有有效材料时跳过且不消耗尝试。
- 使用独立周级模型会话，不与每日会话共用。任务归属日或周由调度器传入，不用执行时的日期替代。
- 回顾保存在本地，不主动发送消息。只有相关话题才注入最多 300 字符的短摘录。

## 来源存在与来源有效

日记中的来源行仍在磁盘上，不代表该内容仍然可用于回顾。用户可能已经纠正或遗忘相应记忆，原始档案和日记并不因此物理消失。

生成前需要同时检查：

1. 日记事件的每个声明来源都存在、属于当前联系人且有非空文本。
2. 来源没有被已删除或已替代的记忆撤回，也没有被已删除经历撤回。
3. 消息 ID、job 引用及关联 memory 引用按现有映射处理，同源别名不算额外的独立证据。

首版保守排除任一声明来源失效的整条事件。若一篇日记还有其他有效事件，可以保留这些事件及其证据；但该篇未经来源拆分的心情、感受和想法全部撤下，避免遗忘内容经主观字段重新进入生成。

召回前再次检查来源日记、原始来源和撤回状态。已生成回顾的任一声明依赖失效，就停止整篇召回；即使正文已经换了说法，也不能只依赖关键词过滤放行。文本 sanitize 保留为补充层。

这些检查使用现有来源映射；尚未覆盖的历史别名不能据此声称全部打通。软删除和停止召回不等于擦除磁盘、聊天服务或备份中的原文。

## 事件身份与生成校验

只在同一天且符合以下之一时合并事件：去标点后的文本完全相同；或共享原始来源、bigram 重合至少 90% 且至少有三个共同 bigram。不同日期的相似表述保持分开，共享一条消息也不能直接证明两件事是同一件事。

生成材料区分日记主观记录与来源原文及角色。返回的 event 必须引用已提供的日记和原始来源；未知 ID、空事件集合均拒绝。来源中的未来或不确定表达与输出的完成表达之间只有窄规则检查，不能当作通用语义验证。

生成结果可以做到 event 级来源可追溯，正文仍没有逐句语义证明。回顾不会自动升级为 confirmed 记忆，不修改人格卡，不把“明天想做什么”转换成执行授权。

## 本轮验证

私有功能参考版本 `9e35cfa`，开发交付报告全量隔离测试 394/394。本次独立运行周回顾 24 项与恢复包 6 项，共 30/30 通过，其中包括：

- 自然周、跨年与夏令时边界、等待主日记、每周一次、失败不自动重试。
- 保守事件合并、未知引用拒绝、来源丢失时不进入生成。
- 真实 ChatEngine 配合合成消息与存储：遗忘后不再将相关事件交给生成器，已改写回顾也不再注入后续请求。
- 双来源部分失效时整条事件排除。
- 同篇日记失去一个来源后，有效事件保留，主观字段及遗忘内容不出现在最终生成 prompt；重开存储后结论保持。
- 维护互斥与包含周回顾表的恢复包回归。

这些都是假模型、合成消息与隔离数据库验证，没有发送真实聊天或强制生成回顾。真实周回顾尚未产生，人物时间、来源支持与阅读体验仍需自然生成后核对。M3 保持“首版已实现，真实生成与质量待验收”。
