# 角色记忆数据的恢复设计

更新日期：2026-10-30。

这份文档描述私有陪伴宿主已实现的离线维护首版，供阅读和后续模块提取参考。公开仓库目前没有这些工具；`SqliteMemoryStore` 的事务、revision 和 FTS 测试不等于已经提供跨库恢复能力。

## 恢复单位

长期记忆与共同经历有相互关联的来源。分别恢复到不同时间点，可能让已删除的内容重新进入回忆，或使进展找不到原事件。恢复材料因此按同一维护窗口打包两库：

| 数据库 | 包含内容 |
| --- | --- |
| 长期记忆库 | 正文、状态、来源、revision、迁移标记、事件记录及索引 |
| 日记与时间线库 | 原始消息与发送状态、共同经历、进展关系、日记条目、系统层、来源、运行记录及待补写任务 |

采用 SQLite 整库快照，避免逐表导出遗漏元数据。FTS 是可重建的派生索引，不是事实源。

恢复包不包含 QQ 登录凭据、DSH 会话、工具权限、QQ 发送队列或完整宿主环境。它不能单独恢复一个可登录、可对话的机器人。

## 同一维护窗口

私有实现将运行登记与普通写入锁分开：

1. 桥接启动时短暂取得同一维护协议的互斥锁，检查条件并登记运行状态，然后释放。
2. 普通存储写入短暂持锁；独立记忆工具不因桥接持续运行而永久被阻塞。
3. 导出、恢复和回滚取得维护锁，并检查运行登记。有活动桥接时拒绝维护。
4. 构造、迁移、建表、索引维护和写入均需要遵守协议；只给业务方法加锁不足以保护初始化。
5. 旧的单库 restore/rebuild 入口也要覆盖完整修改过程，不能只在打开连接时持锁。

这些措施覆盖已接入的项目入口。绕过模块直接写 SQLite 的外部程序不在保护范围内。两个库仍不是跨库 ACID 事务，也不因存在一个锁文件就能自动证明所有磁盘写入者已经停止。

## 包校验

完整包只声明规定的两库和顶层清单。清单记录格式版本、数据库 schema、文件集合、大小、SHA-256、表集合与条数，以及维护窗口和排除项。

校验在不依赖原数据库的情况下完成：

- 拒绝未完成包、空或重复文件清单、缺失/额外文件和路径越界。
- 重新核对文件大小和哈希，对 SQLite 执行 `integrity_check`。
- 验证当前支持的 schema 和实际表集合；未知版本不按默认版本放行。
- 已有包的完整性检查与“它是否等于当前数据库”是两种判断，不能混为一谈。

清单和哈希用于检查完整性，不是可信发布者签名，不证明恢复包来自可信来源。

## 恢复与失败处理

恢复需要显式替换参数和离线维护窗口。先校验源，取得目标目录的维护锁，完成活动桥接等前置检查，再进入修改阶段。前置拒绝不能留下会阻止正常启动的恢复标记。

私有实现先保留旧库，准备待替换文件，并在首次可能修改数据库之前写入未完成标记。两库替换失败时保留标记；桥接启动检查会拒绝使用混合状态。隔离演练覆盖第一库替换后失败、启动被阻断、回滚两库并清除标记。

恢复应保留 deleted/superseded、日记 candidate、来源、原始消息时间和进展关系。日记主观条目不能在恢复中升级为已确认共同经历。待补写任务继续使用原始时间与稳定身份，避免跨日重试另建事件。

恢复的是快照时点，不是合并最新状态。恢复旧快照可能撤销之后的纠正或遗忘。软删除、召回排除和恢复成功都不等于清除了聊天服务、备份或磁盘上的原文。

## 当前证据

私有功能基线 `a5bb191`，开发交付报告全量隔离测试 358/358；本次独立复跑恢复包/互斥专项 6/6。已覆盖合成数据库往返、已有目标恢复、包拒绝、跨进程维护冲突、正常独立记忆工具、旧维护 CLI、失败阻断与回滚。

没有在生产执行 restore/rollback，也没有为这次公开更新启动第二个真实桥接或发送真实 QQ 测试消息。上述测试不证明长期陪伴质量或全场景恢复可靠性；公开仓库的 27 项测试另行计数。

当前任务是继续真实自然事件体验验收。恢复工具按离线维护首版记录，不将其等同于 M1 整体完成。产品状态见 [STATUS.md](STATUS.md)，公开代码范围见 [EXTRACTION.md](EXTRACTION.md)。
